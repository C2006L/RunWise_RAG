# 真实业务接入与回归验证

本轮以现有页面为基础，补齐认证、用户隔离、打卡统计、训练计划和小程序真实请求。没有执行开发数据库迁移，也没有自动更改已有用户的数据归属。

## 首次运行前

1. 备份 `runwise` 数据库。
2. 若尚未执行管理端迁移，先执行 `RunWise_Backend/sql/admin_v1.sql`；已执行时不要重复运行。
3. 在数据库管理工具先查询未删除的重复打卡：

```sql
SELECT user_id, checkin_date, COUNT(*) AS record_count
FROM t_checkin WHERE deleted = 0
GROUP BY user_id, checkin_date HAVING COUNT(*) > 1;
```

有结果时，先人工核对，不要直接删除。无重复后执行一次 `RunWise_Backend/sql/business_v2.sql`。该脚本新增账密凭据表、计划表、问答会话字段和有效打卡唯一约束；不删除既有数据。MySQL DDL 不支持整份脚本事务回滚，若中途失败，请核对已创建的表/列，再从未完成处继续，不要整体重跑。

4. 继续使用原来的 MySQL、Redis、JWT 环境变量启动后端。应用数据库账号需对新增业务表具有查询和增删改权限；建表改表使用数据库管理账号。
5. Web 运行 `npm run dev`。开发配置现在默认真实接口，过去任意账密的 Mock 登录不再有效。首次使用点击“创建账号”，用户名 3–32 位字母/数字/`_.-`，密码 12–128 位。生产上线前仍需结合部署策略控制注册入口及网关流量。
6. 管理端初始化和启动仍见 `runwise-admin/README.md`。管理员和跑者账号独立。

## 两端使用同一账号

- 已有小程序微信账号：微信登录后，在“我的 → 登录 / 绑定 Web 账号”中设置用户名密码，再去 Web 登录。
- 已有 Web 账号：小程序“我的 → 登录 / 绑定 Web 账号”中用同一账密登录。
- 不要在 Web 注册新账号后期待它自动与另一个微信账号合并。绑定接口只给当前用户增加登录方式，不猜测或迁移他人数据。
- 当前沿用单用户一对 Token 的会话策略：另一个客户端重新登录会使旧客户端会话失效。训练数据在同一用户下共享，但暂未实现多设备同时在线。

## 小程序服务地址

开发工具默认 `http://127.0.0.1:8081`。真机调试时，在 `RunWise_MiniProgram/.env.development.local` 写入：

```dotenv
VITE_API_BASE_URL=http://你的电脑局域网IP:8081
```

更改后重启编译。上线时创建 `.env.production.local`，填写已配置到微信后台的 HTTPS API 域名。发布构建前请检查地址，不能将本机地址用于线上。`.local` 文件已忽略，不提交真实环境配置。

## 数据与统计规则

- 打卡时长沿用整数分钟，配速存储为分钟/km；不要把已有时长批量乘或除以 60。
- 配速由后端用时长和距离计算；前端只做预览。
- 每用户每天至多一条未删除记录，唯一约束处理并发重复提交。
- 禁止未来日期及 2000 年以前日期；允许补录历史。
- 当前连续：今天有记录从今天开始，否则从昨天开始，之后不允许跳过缺失日期。
- 历史最长连续：对有效日期去重排序，遇到断档重新计数。
- Web 周视图沿用近七天滚动窗口；`/api/checkin/stats` 的 `weekCount` 为自然周截至今天。两者含义不同，接口不混用。
- 月图表的合计与各天实际里程来自同一组记录；不填充虚构训练数据。
- 新建计划初始为空，未安排日期呈现休息日。计划保存到 MySQL，重复日期返回冲突；状态保持待执行，不因某一天有打卡就冒充完成任务。

## AI 会话与超时

- 分类和热门问题公开；提问、历史、会话、反馈必须认证。
- 上下文同时按用户与 conversationId 过滤。未提供 conversationId 时创建新会话。
- 历史接口新增 conversationId，提问响应新增 id 和 conversationId；既有字段保持兼容。
- Web 点击历史读取完整会话；旧记录无会话标识时仍可打开单条问答。
- 旧调试模式统一写入用户 1 的历史，无法可靠推断真实归属。本轮不重分配、不删除这些数据；正式部署前应人工核对该调试账号的数据。
- 本地小程序旧的未区分用户缓存不自动归属任何账号。旧键保留，新缓存按 userId 隔离。原本仅本地保存的记录不会自动上传，以免把演示数据写入真实账户。
- 模型调用超时 75 秒，Java RAG 请求 85 秒，客户端提问 100 秒。RAG 已耗时超过 5 秒后失败，不再额外等待一轮模型降级；快速失败才允许直连 Ollama。此设置是网络等待上限，不代替网关整体超时和任务取消机制。

## 验证

```powershell
cd D:\RunWise\RunWise_Backend
mvn test
cd D:\RunWise\runwise-web
npm test
npm run build
cd D:\RunWise\runwise-admin
npm run build
cd D:\RunWise\RunWise_MiniProgram
npm run type-check
npm run build:mp-weixin
```

后端测试覆盖 HTTP 认证边界、资料字段白名单、Token 类型与失效、统计断档/跨年/闰日、训练计划用户隔离、注册事务回滚、账号绑定及文章与审计日志事务。数据库测试使用独立 H2，不触碰本地 MySQL；Token CAS 的 Redis 行为在单元测试中模拟，仍需真实 Redis 联调。

Web 另有缓存快照测试：刷新时移除已删除记录、修改日期后清理旧日期。账号切换和退出会重置打卡 Store，在途的旧用户请求不能重新填入新用户缓存。

人工验收：创建两个跑者账号，分别新增打卡和问答，确认历史/统计互不串号；退出后用旧 Token 访问应返回 HTTP 401；同一天重复打卡应返回冲突；绑定同一账密后跨端检查训练数据；补录昨天/断档日期检查连续天数；管理端验证草稿/发布/下架及日志。

管理端第一版仍采用保存已发布文章即转草稿的规则。线上版本/编辑草稿双副本和自动迁移工具属于后续迭代；本轮没有声称这两项已实现。没有进行微信真机、浏览器视觉验收或真实 MySQL/Redis 全链路测试。
