# AI 回答渲染与个性化计划（第一版）

后续已补齐本地/云模型共用入口、多轮长回答上下文和明确的模型错误提示。配置与排错见 [AI 模型切换与排错](ai-model-configuration.md)。

## 运行前

先执行前两轮数据库迁移（`admin_v1.sql`、`business_v2.sql`，已执行时不要重跑）。备份后执行一次 `RunWise_Backend/sql/ai_planning_v3.sql`，新增计划草稿表和问答关联字段。不要执行旧的文章重建脚本。

然后重启 Spring Boot 和 Python RAG 服务，并在 Web、小程序目录运行 `npm ci` 更新依赖。现有 MySQL/Redis/JWT 配置继续使用。

```powershell
cd D:\RunWise
.\venv\Scripts\python.exe code\rag_api.py
```

管理端账号和跑者账号保持隔离。访问问答、摘要、草稿及确认接口必须使用跑者登录身份。

## 如何使用

1. 在 Web 或小程序完成真实登录、打卡或补录。
2. 普通问答会引用当前用户真实训练摘要。标题、列表、表格、引用和代码块以 Markdown 展示，历史消息也使用同一渲染逻辑。
3. 点击答疑页“根据训练记录制定计划”，选择目标、开始日期、每周最多训练次数，补充限制条件并明确确认体感。
4. 生成的是未来7天草稿，未确认时不写课表。核对说明、日期、类型和距离；需要调整时重新打开入口修改要求并再次生成。
5. 点击“确认加入训练计划”，后端从保存的草稿读取内容。在 Web 训练计划页查看和编辑；小程序也可再次打开预览查看保存状态。

## 真实数据如何使用

`RunnerContextService` 只查询认证用户的打卡。查询近56天用于最近记录与变化检查，向模型提供近28天的训练次数、总里程/时长、单次最长距离、加权平均配速、四个七天窗口、填写的经验/频率目标及现有课表。

不发送昵称、身高体重或其他用户记录。没有记录不能推断用户完全没有运动；缺失字段保持缺失，不填写示例数据。平均配速单位为分钟/km，由总时长除以总里程计算。

当前精确课表要求至少两条近期有效记录，最近一周有记录，并明确确认近期无疼痛或明显不适。达不到条件会返回补充信息提示，仍可使用普通问答讨论训练经历。数据门槛是产品的首版规则，不是医学判断。

## 计划边界与保存规则

- 仅生成未来7天，开始日期最早明天，结束日期须落在现有四周课表窗口内。
- 目标为习惯维持、5K/10K 基础或体能提升，不承诺成绩或替代专业训练评估。
- 本版先由真实记录推导合法候选，模型只选择日期安排并解释理由，不自由改写日期/距离。候选只安排轻松跑和休息，属于首个保守基础周；暂不提供专项速度课、比赛成绩预测或递增周期。
- 候选次数不超过用户可用次数和近期已记录的周平均频率（向上取整）；7天总距离不得超过近28天记录的四周均值，单次不得超过近期已记录的最长距离。等量分配后保留两位小数向下取整，不为凑满预算增加跑量。
- 至少安排休息，连续跑步不超过2天，质量训练最多1次；规则版本为 `conservative-week-v1`。这些是保守产品边界，并不保证适合所有人的身体状况。
- 模型输出必须是合法的完整结构化课表。日期、类型、距离或恢复安排校验失败时拒绝整份草稿，不偷偷修正数字或补齐内容。
- 草稿保存请求、真实摘要快照、模型名、检索集合版本、来源及规则版本，24小时内可确认。
- 确认只提交草稿 ID；不能从前端替换课表内容或用户 ID。用户身份和所有权由后端检查。
- 记录、日期或规则变化后必须重新生成。已有日期的课表不会被覆盖，提示冲突后由用户决定如何调整。
- 确认使用数据库事务与行锁；重复或并发确认同一草稿只写一次，任何一天插入失败都会回滚整组课表。

## Markdown 与历史

两端共用 `shared/markdown-policy.mjs`。原始 HTML 和图片关闭，只允许 HTTP/HTTPS 链接，外链带隔离属性。模型文本不会直接作为可执行 HTML 使用。表格独立横向滚动，正文仍保持正常换行。复制得到原始 Markdown。

计划说明与草稿 ID 保存到真实问答历史。Web 历史重新打开会还原预览；小程序本地会话保留草稿 ID，服务端历史也可以打开预览。小程序原生 rich-text 的外链交互受平台限制，不等同于浏览器链接导航。

## 接口与验证

新增接口：

- `GET /api/qa/training-context`
- `POST /api/qa/plan-drafts`
- `GET /api/qa/plan-drafts/{id}`
- `POST /api/qa/plan-drafts/{id}/confirm`
- Python 内部：`POST /api/rag/plan`

生成请求只接受目标、日期、频率、体感确认、补充要求和可选会话 ID；训练总量和用户 ID 不接受前端指定。缺失信息返回 `NEEDS_INPUT`，不会调用模型或创建课表。

可选真实 Ollama 冒烟测试：`venv\Scripts\python.exe code\smoke_ai_plan.py`。它只使用明确标注的测试摘要，不写业务数据库。小模型可能超时、截断 JSON 或生成不符合边界的结果；系统会拒绝这些输出。上线更换模型后需用同一套数据重新评测，不能仅以一次成功证明训练建议质量。
